# 장바구니 할인 계산기 PRD

## 1. 목적

주문 담당자가 장바구니의 상품 합계를 계산하고, 문턱 할인과 VIP 추가 할인을 정해진 순서로 적용하여 할인 금액을 오류 없이 확정할 수 있게 한다.

계산 순서는 다음과 같다.

1. 상품 합계 계산
2. 문턱 할인 적용
3. VIP인 경우 추가 5% 할인 적용

## 2. 증거 수준

| 수준 | 정의 |
|---|---|
| L0 | 인터뷰 메모에 실제 결과, 고정 규칙 또는 미확인 상태가 명시됨 |
| L1 | 구체적 사례나 수치로 뒷받침되지만 일반 규칙으로 완전히 확정되지는 않음 |
| L2 | 인터뷰 메모로부터 추론만 가능함 |

## 3. 아키텍처

| ECB 계층 | 구성 요소 | 책임 |
|---|---|---|
| Entity | `Cart`, `Money` | 품목과 금액을 표현하고 상품 합계 및 할인 금액의 상태를 보유한다. |
| Control | 계산 함수 | 상품 합계, 문턱 할인, VIP 추가 할인을 순서대로 계산하고 입력 오류를 통제한다. |
| Boundary | 주문 폼 | 품목, 수량, VIP 여부를 입력받고 계산 결과 또는 통제된 오류를 표시한다. |

## 4. 명세

### 4.1 INV — 불변식

| ID | 명세 | 증거 수준 | ECB 계층 | 테스트 아이디어 |
|---|---|---|---|---|
| INV-1 | 주문 금액이 문턱 할인의 적용 대상이면 할인 금액은 할인 전 상품 합계의 10%이고, 할인 후 금액은 상품 합계의 90%여야 한다. | L1 | Entity | 상품 합계 66,000원에 대해 할인액 6,600원과 할인 후 금액 59,400원을 확인한다. |
| INV-2 | VIP 주문에는 문턱 할인을 먼저 적용하고, 그 결과에 VIP 할인 5%를 추가 적용해야 한다. | L0 | Control | 중간 금액을 관찰하여 문턱 할인 결과에 VIP 할인이 적용되는지 확인한다. |
| INV-3 | 동일한 주문에서 VIP 할인과 문턱 할인의 적용 순서는 문턱 할인 후 VIP 할인으로 고정되어야 한다. | L0 | Control | 계산 진입 경로와 관계없이 할인 적용 순서가 유지되는지 확인한다. |

### 4.2 E — 예외 및 경계

| ID | 명세 | 증거 수준 | ECB 계층 | 테스트 아이디어 |
|---|---|---|---|---|
| E-1 | 수량이 -1인 품목을 포함한 주문은 정상 합계 0원으로 처리되어서는 안 되며 오류로 처리되어야 한다. | L1 | Boundary | 수량 -1을 제출했을 때 정상 금액 대신 오류가 표시되는지 확인한다. 오류 형식은 단정하지 않는다. |
| E-2 | `items`가 없는 주문은 처리되지 않아야 하며 서버 내부 오류인 500 응답으로 종료되어서는 안 된다. | L1 | Boundary | `items`가 없는 주문을 제출해 통제된 오류가 반환되고 500이 발생하지 않는지 확인한다. 기대 오류 코드는 단정하지 않는다. |
| E-3 | 상품 합계가 정확히 50,000원일 때 문턱 할인을 적용하는지는 현재 확정되지 않았다. 확정 전까지 적용 또는 미적용을 명세로 단언해서는 안 된다. | L0 | Entity | 정확히 50,000원인 경계에 특정 할인 결과를 기대하는 명세나 테스트가 없는지 확인한다. |

### 4.3 AC — 인수 기준

| ID | 명세 | 증거 수준 | ECB 계층 | 테스트 아이디어 |
|---|---|---|---|---|
| AC-1 | **Given** A의 단가가 12,000원이고 수량이 3개이며 B의 단가가 30,000원이고 수량이 1개일 때, **When** 주문 할인 금액을 계산하면, **Then** 할인 전 합계는 66,000원이고 10% 할인 후 금액은 59,400원이어야 한다. | L0 | Control | 예시 품목과 수량으로 계산해 66,000원과 59,400원을 확인한다. |
| AC-2 | **Given** 문턱 할인과 VIP 할인이 모두 적용되는 주문일 때, **When** 최종 금액을 계산하면, **Then** 문턱 할인 적용 후 금액에 VIP 할인 5%가 적용되어야 한다. | L0 | Control | 중간 계산 결과와 최종 결과를 각각 확인한다. |
| AC-3 | **Given** 품목 수량으로 -1이 입력되었을 때, **When** 주문을 계산하거나 제출하면, **Then** 합계 0원의 정상 주문으로 표시되지 않고 오류로 처리되어야 한다. | L1 | Boundary | 응답이 성공이 아니며 정상 합계 0원을 표시하지 않는지 확인한다. |
| AC-4 | **Given** 요청에 `items`가 없을 때, **When** 주문을 제출하면, **Then** 시스템은 500이 아닌 통제된 오류 결과를 반환해야 한다. | L1 | Boundary | 응답 상태가 500이 아니며 오류 결과로 식별되는지 확인한다. |

### 4.4 U — 사용 시나리오

| ID | 명세 | 증거 수준 | ECB 계층 | 테스트 아이디어 |
|---|---|---|---|---|
| U-1 | 주문 담당자는 품목별 단가와 수량으로 상품 합계를 계산하고 문턱 할인을 적용한 최종 금액을 확정할 수 있어야 한다. | L1 | Control | A 3개와 B 1개 사례에서 별도 엑셀 계산 없이 기대 금액을 얻는지 확인한다. 시간 기준은 추가하지 않는다. |
| U-2 | 주문 담당자는 VIP 주문에서 문턱 할인 후 VIP 할인이 적용된 금액을 확정할 수 있어야 한다. | L1 | Control | 두 할인이 적용되는 주문에서 적용 순서와 각 단계의 금액을 확인한다. |

## 5. 범위 밖 — 과잉 구현 금지

| ID | 범위 밖 항목 | 근거 |
|---|---|---|
| OOS-1 | 쿠폰 적용 여부와 계산 규칙 | 인터뷰 메모에 언급이 없으므로 현재 인수 범위에 포함하지 않는다. |
| OOS-2 | 배송비의 합계 포함 여부와 계산 규칙 | 인터뷰 메모에 언급이 없으므로 현재 인수 범위에 포함하지 않는다. |
| OOS-3 | 정확히 50,000원일 때의 문턱 할인 적용 여부 | 적용 여부가 확인될 때까지 어느 동작도 임의로 구현하지 않는다. |
| OOS-4 | 오류 메시지 문구와 `items` 누락 시의 구체적인 오류 상태 코드 | 통제된 오류여야 한다는 사실 외에는 확인된 요구사항이 없다. |
| OOS-5 | 계산 완료 시간 또는 성능 목표 | 엑셀 검산에 10분이 걸렸다는 사례만 있으며 제품 성능 기준은 제시되지 않았다. |

이 절은 제품에서 영구 제외한다는 의미가 아니다. 추가 증거와 결정이 생기기 전까지 구현 및 인수 기준에 포함하지 않는다는 의미다.

## 7. 미결정 사항

- 상품 합계가 정확히 50,000원일 때 문턱 할인을 적용하는지 확인이 필요하다.
- 수량 오류와 `items` 누락에 사용할 구체적인 오류 형식 및 상태 코드는 확인이 필요하다.
