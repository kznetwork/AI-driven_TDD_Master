# 분기 지도 (gilded_rose.py 의 update_quality() — 읽기만 했다)

| 조건 | 하는 일 | 규칙 |
|---|---|---|
| name ∉ {Brie, Backstage}, quality > 0, ≠ Sulfuras | quality -1 | R-1 · R-3 |
| name == Aged Brie, quality < 50 | quality +1 | R-4 · R-5 |
| name == Backstage, quality < 50 | quality +1 (sell_in < 11 이면 +1, < 6 이면 +1 더) | R-7 |
| name ≠ Sulfuras | sell_in -1 | R-1 |
| sell_in < 0 (판매일 후), 일반 | quality 추가 -1 (0 초과일 때, ≠ Sulfuras) | R-2 |
| sell_in < 0 (판매일 후), Backstage | quality = 0 | R-7 |
| sell_in < 0 (판매일 후), Aged Brie, quality < 50 | quality 추가 +1 | R-4 |

## 규칙표에 대응하지 않는 분기 (의도 불명)
- quality 가 50 초과 · 0 미만으로 **들어온** 입력은 요구사항에 없다 → 특성화 테스트로 현재 동작을 기록한다 (docs/특성화.md)
- 이름이 정확히 일치하지 않는 아이템은 모두 '일반'으로 처리된다 → 특성화

## 위험 지점 (리팩터링 전에 테스트 필요)
1. sell_in 감소 위치를 옮기면 판매일 후 경계가 `< 0` → `< 1` 로 바뀐다 → 경계 짝 테스트 (TC-02 · TC-06)
2. Backstage 의 `quality < 50` 검사가 3곳에 흩어져 있다 → Backstage 경계 parametrize (TC-04~06)
3. 아이템 이름 문자열이 7곳에 반복된다 → 오타 한 글자가 규칙을 바꾼다 (상수 추출, A.4)
4. Conjured 를 넣을 자리가 없다 → 새 분기를 추가하면 기존 분기와 섞인다 (A.6 에서 TDD)
5. 같은 for 루프 안에서 quality 와 sell_in 을 모두 바꾼다 → 순서가 곧 동작이다
