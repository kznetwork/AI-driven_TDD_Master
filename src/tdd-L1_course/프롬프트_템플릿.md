# 프롬프트 템플릿 — L2 · AI 시대의 TDD

실습이 끝난 뒤 실제 업무에서 그대로 꺼내 쓰는 용도입니다. 실습 순서대로 쓴 프롬프트는
각 프로젝트 폴더의 `prompts.md` 에 있습니다.

## 모든 프롬프트의 기본형 — 네 줄
```text
@<대상 파일들>                      ← 무엇을 보고
<무엇> 만 <해줘>.                    ← 범위를 좁히고
테스트 파일은 수정하지 마.            ← 금지를 말하고
끝나면 !pytest -q --tb=short 결과를 보여줘.   ← 확인을 요구한다
```
꺾쇠 `< >` 부분만 바꿔서 씁니다.

## GREEN — 테스트 하나 통과
```text
@tests/test_<모듈>.py @src/<모듈>.py
<테스트 이름> 만 통과하는 최소 구현을 해줘.
테스트 파일은 수정하지 마. 다른 기능은 추가하지 마.
끝나면 !pytest -q --tb=short 결과를 보여줘.
```

## REFACTOR — 동작은 그대로, 한 가지만
```text
@src/<모듈>.py 모든 테스트가 통과하는 상태야.
동작은 바꾸지 말고 <정리할 것 하나> 만 해줘.
테스트 파일은 수정하지 마. 끝나면 !pytest -q --tb=short 결과를 보여줘.
```

## REVIEW — 수정 없이 검토 (plan 모드)
```text
@tests/test_<모듈>.py 테스트를 검토만 해줘. 파일은 수정하지 마.
관점: 테스트 이름, AAA 구조, 한 테스트에 한 규칙, 빠진 경계값.
표로: 테스트 | 문제 | 제안
```

## 회귀 복구 — 기존 테스트가 깨졌을 때
```text
@tests/test_<모듈>.py @src/<모듈>.py
방금 변경으로 기존 테스트 <N>개가 실패해. <새 요구사항>과 기존 동작을 모두 지원해서
모든 테스트를 통과시켜줘. 테스트 파일은 수정하지 마. 끝나면 !pytest -q --tb=short 결과를 보여줘.
```

## 예시 표 빈틈 찾기 (plan 모드)
```text
아래 <기능> 예시 표를 검토만 해줘. 새 규칙을 만들지 말고,
빠진 경계값이나 서로 충돌하는 규칙만 질문 형태로 알려줘.
(예시 표 붙여넣기)
```

## 리팩터링 후보 고르기 (plan 모드)
```text
@src/<모듈>.py 모든 테스트가 통과하는 상태야. 동작은 바꾸지 않고 읽기 쉽게 만들 리팩터링 후보를
작은 것부터 3개 이하로 제안만 해줘. 파일은 수정하지 마.
```

## GEMINI.md — 프로젝트 규칙 (프로젝트 폴더 최상단)
```markdown
# 이 프로젝트의 규칙
- tests/ 아래 파일은 절대 수정하지 않는다.
- 요청받은 테스트를 통과하는 데 필요한 코드만 쓴다.
- 요구사항은 docs/예시표.md 가 기준이다.
- 변경 후에는 pytest -q --tb=short 결과를 보여준다.
- 테스트가 틀려 보이면 고치지 말고 나에게 질문한다.
```
저장 후 Gemini CLI 에서 `/memory refresh` → `/memory show` 로 로드됐는지 확인합니다.

## 3장 작업별 패턴 — 진단 · 리뷰 · 리팩터 · 테스트
```text
[진단] «대상»의 코드 스멜·중복·복잡도를 찾아줘. 수정 말고 [위치|유형|근거|난이도] 표로, 우선순위 순으로 정리해줘.
[리뷰] 방금 변경을 «보안|회귀|성능» 관점으로만 리뷰해줘. 동작이 바뀔 지점과 그걸 잡을 테스트가 없는 부분을 우선순위로.
[리팩터] «함수»의 외부 동작을 바꾸지 말고 내부 구조만 개선해줘. 먼저 계획을 보여주고 승인 후 적용, 매 단계 후 테스트 실행.
[테스트] «함수»의 테스트 갭을 찾아줘(경계·예외·중복). 빠진 케이스를 먼저 보여주고, 합의된 케이스만 테스트로 추가해줘.
```
진단은 plan 모드(`gemini --approval-mode plan`), 수정은 기본 모드에서 한 번에 하나씩.

## 이렇게 쓰지 않습니다
| 나쁜 예 | 무엇이 빠졌나 |
|---|---|
| `덧셈 계산기 만들어줘. 테스트도 같이 짜주고 잘 돌아가게 해줘.` | 테스트를 사람이 쓰지 않음 · 범위 · 확인 없음 |
| `@src/calculator.py 세미콜론도 구분자로 쓸 수 있게 바꿔줘.` | 기존 동작 유지 조건 · 확인 없음 → 회귀 |
| `@tests/test_cart.py @src/cart.py 테스트가 다 통과하게 고쳐줘.` | 금지 줄 없음 → AI가 테스트를 고친다 |
| `코드가 좀 지저분하네. 깔끔하게 정리해줘.` | '무엇 하나'를 정하지 않음 → 경계 조건이 바뀐다 |
